# DT 預設接收完整 SBOM，OSV 失敗門檻以完整 SBOM 判定

原本只產生排除開發套件的 SBOM，開發工具鏈的已知弱點因此永遠不會被發現。現在每次執行都產生產品 SBOM 與完整 SBOM。DT 專案預設接收完整 SBOM，可以用「DT 上傳版本」切回產品 SBOM；OSV 失敗門檻也只以完整 SBOM 的 OSV 結果判定，所以開發套件的弱點同樣會擋 DT 並讓 Task 失敗。

這推翻了「DT 專案只接收交付產品 SBOM」的既有假設：DT 中的組件數、授權統計與弱點會包含不隨產品部署的開發套件。我們接受這個代價，換取開發套件弱點的能見度。另一種做法是門檻只看產品 SBOM、開發套件弱點只警告不擋，這個做法被拒絕，因為它會保留原本的盲點。完整 SBOM 與產品 SBOM 來自同一次依賴安裝與同一份 lockfile，所以完整 SBOM 涵蓋產品 SBOM，只看完整 SBOM 就等於兩份都看。
