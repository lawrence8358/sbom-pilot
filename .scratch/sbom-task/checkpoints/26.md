## 完成內容與新介面

- `src/command-log.ts` 新增 `taskLogIssue(type: 'error' | 'warning', message: string): string`，使用現有相依套件 `azure-pipelines-task-lib/taskcommand` 的 `TaskCommand` 序列化，不直接呼叫 SDK 的 issue／結果狀態 API。
- 外部欄位只進入訊息區，命令及 type 屬性固定；SDK 將 `%`、CR、LF 轉為 `%AZP25`、`%0D`、`%0A`。依 SDK 規則，`;`／`]` 在訊息區是普通文字，保留以正確顯示；OSV URL 的每個 ID 另以 `encodeURIComponent` 編碼。測試含所有外部欄位的換行、`;`、`]`、百分比編碼及假 `task.complete` 命令，驗證輸出僅一行且 SDK 解析後只有原來的 warning 屬性、完整原訊息。
- `src/osv-issues.ts` 新增 `logOsvIssues(groups: { exceeded: readonly OsvFinding[]; below: readonly OsvFinding[] }, log: (message: string) => void): void`。
  - 接收既有門檻分組，exceeded 輸出 error、below 輸出 warning，不重新定義門檻。
  - 依危急、高、中、低、無、未知穩定排序；同級保留原順序，不修改原清單。
  - 每類顯示風險最高的前 50 筆，超出時另補一則同類型「另有 N 筆，詳見 OSV 弱點報告」；恰好 50 筆不補摘要。
  - 每筆含套件、版本、生態系、中文風險等級、全部 ID／CVE／修復版本及各 ID 的 OSV URL；缺 CVE／修復版本時為「未提供」。
- `runWorkflow` 在 OSV 成功後重用同一次 `partitionOsvFindings` 結果，透過 `services.log` 輸出 issue；`WorkflowServices` 沒有新增服務。OSV 技術失敗不輸出弱點 issue；沒有弱點及未啟用 OSV 時也不輸出。
- `scanOsv` 移除舊 `##[warning]OSV 發現已知弱點...` 單行 log，保留無弱點的完成訊息。
- 門檻、DT 阻擋、發佈順序、錯誤彙整及成功／失敗語意維持工單 25 實作；完整報告／摘要仍取得全部 findingList，無論 issue 是否被上限省略。
