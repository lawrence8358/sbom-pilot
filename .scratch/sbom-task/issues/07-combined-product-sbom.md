# 07: 前後端合併為同一交付產品的 SBOM

Status: ready-for-agent
Blocked by: 02, 03, 04, 05

**What to build:** 使用者選擇前後端合併模式並提供共同根目錄後，Task 使用既有前端及 .NET 還原能力準備依賴，再以一次遞迴掃描產生涵蓋同一交付產品前後端的單一 SBOM 成品。

## Acceptance criteria

- [ ] 提供合併模式，掃描輸入為共同根目錄，與原需求的根目錄 workspace 範例一致；不要求兩個各自必填的前後端掃描路徑。
- [ ] 從正確 workspace 根目錄依管理器辨識結果使用 npm、pnpm 或 Yarn 準備前端依賴，並使用現有 .NET 流程還原後端；管理器宣告、嚴格鎖檔及 SDK 選擇契約維持一致。
- [ ] 以同一次遞迴 dotnet/js 掃描產生單一 SBOM，前後端共同作為一個交付產品；不先產生兩份 SBOM 再自行合併。
- [ ] 共用排除規則可依前後端相對目錄各自排除，正確保留花括號 glob；預填共通規則可修改，專案特有目錄不會成為所有產品的固定排除。
- [ ] 沿用 required-only、指定 Spec Version 與有效 JSON 格式驗證；依賴準備完成後不再次讓掃描工具安裝依賴。
- [ ] 至少驗證原需求對應的 pnpm workspace 與 .NET 合併範例，並涵蓋 npm/Yarn 的既有還原路徑；單一成品可觀察到前後端組件與可取得的依賴關係，排除項目結果符合設定。
- [ ] README 補上合併模式的根目錄概念、前置條件、共用排除設定與 Classic Build/YAML 範例；產出保留單一 DT 專案對應的產品邊界。

## Comments

- 使用者已核可本工單及其阻擋關係；遵循前後端共同作為交付產品的既有領域決策。
