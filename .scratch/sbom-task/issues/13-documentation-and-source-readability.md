## Acceptance criteria

- [ ] README.md 依「用途、支援與前置條件、安裝、最小操作、各模式、設定、進階連結、問題排查」安排，使用完整可讀的正體中文；測試歷史與內部實作細節移至適當文件，保留必要參數與限制。
- [ ] README-Dev.md 清楚說明開發環境、建置／測試／打包、程式分工、維護與發佈；加入 Mermaid 流程圖，對應實際四模式分流、工具及依賴準備、單次掃描、Schema 驗證、選用 DT、有效成品與錯誤處理。
- [ ] src/**/*.ts 具有一致縮排、換行、空白行與可閱讀的敘述區塊，提供可重跑的格式化檢查；保留內嵌腳本、正規表示式、字串及秘密先載入順序的語意。
- [ ] src 內具名函式、方法及具名函式型常數都有有意義的中文用途註解；複雜函式另說明重要輸入／回傳／失敗與清理行為，避免用泛用模板重複名稱。匿名短回呼不要求逐個加無意義註解。
- [ ] 檢視認證設定、網路生命週期、SDK／還原及壓縮檔驗證等複雜處，提取有明確責任的內部函式，減少長函式與深層分支；保留既有對外介面，避免新增沒有實際用途的抽象層。
- [ ] 重構前後以現有測試、型別／格式檢查及受影響的實際 Windows／Linux 封裝流程驗證；不弱化認證隔離、鎖檔、清理、required scope、單次合併掃描與 DT 失敗後有效成品行為。
- [ ] 提交可續接 checkpoint，記錄變更、完成／未完成區域、驗證結果與剩餘工作；最終整合後再進行兩軸 code review。
